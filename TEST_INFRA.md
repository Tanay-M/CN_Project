# Test Infrastructure & E2E Requirements Verification (TEST_INFRA.md)

## 1. Executive Summary & Testing Philosophy

The CarbonRoute carbon-aware traffic engineering testbed operates under a **Dual-Track Verification Protocol**:
1. **Implementation Track**: Developing multi-seed campaigns (R1), parameter sensitivity sweeps (R2), and manuscript elevation (R3).
2. **Requirements Verification Track**: Developing an independent, opaque-box, 4-tier verification suite (`tests/test_e2e_requirements.py`) that audits system behaviors, interface contracts, physical and mathematical invariants, and manuscript-to-artifact reconciliation without coupling to private heuristic states.

### Core Testing Principles
- **Behavioral & Invariant Testing**: Tests assert mathematical invariants (e.g., quantile monotonicity, hysteresis non-increasing route flaps, p-value bounds in $[0.0, 1.0]$, Pareto non-dominance) rather than duplicating private implementation logic.
- **Authoritative Expected Output Derivation**: Every test derives its ground truth either from reference programs (e.g., `scipy.stats` paired t-tests, `verify_results.py` 8-stage auditor, SNDlib topology graph) or documented mathematical contracts in `PROJECT.md` and `CODING_STANDARDS.md`.
- **Progressive Testability**: The test suite operates progressively across project milestones (M1 through M5). Tests validate contract specifications and schema validators synchronously on contract fixtures, while dynamically validating campaign and sensitivity artifacts as they are generated by subsequent milestones.
- **Forensic Integrity**: No synthetic shortcuts, no hardcoded passing facades, and no masked errors. All physical units (Mbps, g CO2/kWh, minutes) and timing lags are audited strictly.

### Tier 1: Feature Coverage
Validates the structural format, schema compliance, and environmental prerequisites of the features introduced across R1–R4:
- **Multi-Seed Output Schema (`test_tier1_multiseed_output_schema`)**: Enforces that multi-seed campaigns provide at least 5 distinct random seeds (e.g., $S = \{42, 43, 44, 45, 46\}$), separate seed directories (`results/seeds/seed_{seed}/`), and summary statistics including mean and standard deviation for key performance indicators (`overload_minutes`, `forwarding_score`, `served_fraction`, `route_changes`).
- **Statistical Significance Format (`test_tier1_statistical_significance_json_format`)**: Enforces JSON schema containing comparisons against `reactive_carbon` and `persistence_carbon`, reporting `mean_diff`, `std_diff`, `t_statistic`, `p_value_ttest`, `wilcoxon_stat`, and `p_value_wilcoxon`.
- **Parameter Sensitivity Format (`test_tier1_sensitivity_sweep_data_format`)**: Audits sensitivity grid schema over $\alpha \in [0.70, 0.99]$ and $\tau \in [0.00, 0.20]$ under observation delay $d \in \{0, 1\}$.
- **Manuscript Section Audits (`test_tier1_manuscript_threats_to_validity_presence`, `test_tier1_manuscript_simulation_fidelity_presence`)**: Validates presence of dedicated sections covering "Threats to Validity" (Internal, External, Construct, Conclusion) and "Simulation Fidelity vs. Real Queuing Dynamics" (fluid progressive-filling vs. packet queuing/TCP) in `docs/PAPER_DRAFT.md`.
- **Windows CPU Environment Compliance (`test_tier1_windows_cpu_command_compliance`)**: Enforces that execution operates natively on Windows CPU without requiring CUDA or GPU drivers, with `$env:PYTHONPATH="src"` or `pyproject.toml` Python path discovery, and thread concurrency bound by `cpu_threads`.

### Tier 2: Boundary & Corner Cases
Stress-tests boundary values, numerical degeneracies, and mathematical monotonicity:
- **Zero Overload Minutes (`test_tier2_zero_overload_minutes_handling`)**: Validates that runs with zero overload minutes (e.g. low-demand periods or conservative shortest paths) do not cause division-by-zero errors in relative difference calculations, yield non-negative excess Mbit, and maintain finite metrics.
- **P-Value Bounds (`test_tier2_p_value_bounds_strict`)**: Verifies that all p-values generated by parametric (`ttest_rel`) and non-parametric (`wilcoxon`) tests remain strictly bounded within $[0.0, 1.0]$ across edge cases (identical vectors, orthogonal vectors, large differences).
- **Quantile Margin Monotonicity (`test_tier2_alpha_quantiles_monotonicity`)**: Verifies that calibration margin $m_h(\alpha)$ is monotonically non-decreasing with respect to $\alpha \in [0.70, 0.99]$ across all forecast horizons $h \in \{1, 2, 3\}$.
- **Hysteresis Monotonicity (`test_tier2_tau_hysteresis_route_change_monotonicity`)**: Verifies that increasing the route-change improvement threshold $\tau$ monotonically decreases or preserves the number of elective route changes.
- **Physical Metric Bounds (`test_tier2_non_negative_metrics_and_physical_bounds`)**: Asserts that `forwarding_score >= 0.0`, `overload_minutes >= 0.0`, `excess_mbit >= 0.0`, `served_fraction in [0.0, 1.0 + 1e-6]`, and `route_changes >= 0`.

### Tier 3: Cross-Feature Interactions
Validates algorithmic pipelines combining multiple subsystems:
- **Paired Hypothesis Testing Pipeline (`test_tier3_paired_statistical_significance_computation`)**: Evaluates paired differences matched strictly on identical `(window, carbon_year, scenario, observation_delay_bins)` instances between GNN+Safeguards vs. Reactive Carbon and Persistence+Safeguards. Confirms statistical significance on congested workloads.
- **Tri-Objective Pareto Frontier Characterization (`test_tier3_sensitivity_pareto_frontier_non_dominated_sorting`)**: Tests non-dominated sorting over the tri-objective trade-off:
  1. $\min f_1 = \text{Forwarding Carbon Score}$
  2. $\min f_2 = \text{Route Flap Rate (changes/day)}$
  3. $\min f_3 = \text{Overload Duration (minutes/day)}$
  Verifies that points labeled as Pareto-optimal are mutually non-dominated and that no dominated points are retained.
- **Manuscript-to-Artifact Reconciliation (`test_tier3_manuscript_numerical_claims_match_artifacts`)**: Parses markdown tables from `docs/PAPER_DRAFT.md` and audits every numerical cell against summary run artifacts with a strict absolute tolerance of $\pm 0.01$.

### Tier 4: Real-World Acceptance Scenarios
End-to-end integration and independent auditing:
- **Auditor Verification (`test_tier4_verify_results_auditor_all_directories`)**: Runs `scripts/verify_results.py` over all generated output directories (`results/paper`, `results/demo`, and dynamically any `results/seeds/seed_*` or `results/sensitivity`), verifying manifest Schema v2, SHA-256 hashes, physical link capacity constraints ($\le 10$ Mbps), loop-free routes, and causal observation timing.
- **Baseline Unit Test Suite Pass Rate (`test_tier4_baseline_unit_test_suite_passes`)**: Executes the baseline unit test suite (`test_causality.py`, `test_data.py`, `test_prediction.py`, `test_routing.py`, `test_service.py`) and guarantees a 100% pass rate.
- **Summary and Manifest Reconciliation (`test_tier4_summary_reports_reconcile`)**: Audits run count parity and cryptographic integrity between `manifest.json` and `summary.csv`.

## 4. Progressive Testability Framework

To support iterative milestone delivery without breaking continuous integration:
1. **Pre-Flight Contract Validation**:
   Every schema and invariant validator function (e.g., `validate_multiseed_summary`, `validate_significance_json`, `validate_sensitivity_summary`, `is_pareto_efficient_tri_objective`) is immediately tested against synthetic valid and invalid contract fixtures. This guarantees the test logic is exercised, debugged, and verified in Milestone 1.
2. **Dynamic Artifact Inspection**:
   When an artifact directory (e.g., `results/multiseed/`, `results/sensitivity/`) is not yet generated by an upcoming milestone (M2, M3, or M4), the test reports an informative diagnostic message and invokes `pytest.skip("Pending Milestone X: ...")`.
3. **Automatic Promotion**:
   As soon as Milestone 2 or 3 generates campaign outputs, running `pytest tests/test_e2e_requirements.py` automatically promotes those checks from skipped to actively executing full disk verifications.

## 5. Execution Instructions & Environment Setup

### Environment Requirements
- **OS**: Windows 10 / Windows 11 (PowerShell `pwsh`)
- **Python**: 3.10+
- **PyTorch**: Deterministic CPU execution (`torch.set_num_threads(2)`)
- **Environment Variable**: `$env:PYTHONPATH="src"`

### Test Execution Commands
```powershell
# Run the E2E Requirements Verification Suite
$env:PYTHONPATH="src"; pytest tests/test_e2e_requirements.py -v

# Run the complete test suite (Unit + E2E)
$env:PYTHONPATH="src"; pytest tests/ -v

# Audit generated experimental campaign directories
$env:PYTHONPATH="src"; python scripts/verify_results.py results/paper
$env:PYTHONPATH="src"; python scripts/verify_results.py results/demo
```
